# Project 3 Analysis

## Program Overview

This program reads a binary file and prints a hex dump. Each line shows:

- the byte offset
- sixteen bytes in hexadecimal
- the ASCII version of those bytes

Characters that are not printable ASCII are replaced with `.`.

## Validation

I checked the binary files hexdump generated by my program against the Linux command:

```bash
hexdump -Cv data/binary.out
```

The bytes and ASCII output matched. 
I saved the output in `outputs/hexdump_program.txt` and the Linux command output in `outputs/hexdump_linux.txt`.

## Optimization Differences

The assembly files were generated using -S with `-O0`, `-O1`, and `-O3`.

| Optimization Level | Assembly Lines |
|---|---:|
| `-O0` | 200 |
| `-O1` | 207 |
| `-O3` | 237 |

Looking at the code for the `-O0` assembly, it is the easiest to follow because it remains closest line by line to the original C code. The loops and variables are easier to match back to the source program. This makes using `-O0` useful for if I wanted to debug or understand the assembly without access to the source code.

The `-O1` assembly applies some optimization. It uses registers more actively (for example `%rbx` and `%rbp`) and changes the structure of the code compared with `-O0`. This makes the assembly less of a direct copy of the C source code, but more efficient.

The `-O3` assembly is the longest (237 lines) even though it is the most optimized. The compiler rearranged instructions and loops to improve performance.

For example, the `-O3` assembly includes:

```asm
.p2align 4
```

It also created a separate `main.cold` section for less common code, such as the error path. This shows that the compiler reorganized the assembly to help it run more efficiently.

## Conclusion

All three optimization levels produce the same output. The main difference is how the compiler translates the C code into assembly.

For this program, optimization probably doesn't make a large runtime difference because most of the work is file reading and formatted printing, rather than heavy computation.
